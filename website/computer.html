Connect your computer.

Pair your own Mac with Gepetel and it can use it for you — from your private chat only, never from a group. The Mac dials out to Gepetel, so nothing listens on your machine and there is no port to forward.

Early days: today this is a small command-line agent you install yourself, so it suits you if a Terminal window doesn't scare you. The one-click app is being built — ask Gepetel to tell you when it's ready.

What it can do today

  • Say whether your computer is on — and what it can currently do.
  • Read a web page on your machine — fetched from your own connection, then boiled down on the Mac to just the passages that answer your question, so the answer comes back fast and cheap instead of a whole page.

Coming next: a sandboxed Linux shell for real work, and your own logged-in Chrome for things that need a browser.

Before you start

  • A Mac you can leave on.
  • Node 22 or newer — check with node -v.
  • Terminal, and about two minutes.

1Install the agent

One time only. It lives in your own copy of Gepetel's open-source repository:

git clone https://github.com/bogdanripa/gepetel.git
cd gepetel/agent
npm install
npm run build
npm link        # gives you the `gepetel-agent` command

If npm link asks for a password, run it with sudo — or skip it and use node dist/index.js wherever the steps below say gepetel-agent.

2Get a code, in the chat

In your private chat with Gepetel, say "connect my computer". It replies with a six-digit code. The code lasts ten minutes and works once, so get it after step 1 is done — if it expires, just ask again.

Then, in Terminal:

gepetel-agent pair 123456   # your code, not this one
gepetel-agent run

Gepetel messages you in the chat the moment it's connected. Ask it "is my computer on?" to see for yourself.

3Keep it running

gepetel-agent run lives as long as that Terminal window. To have it start at login and come back by itself, run this from the gepetel/agent folder:

cat > ~/Library/LaunchAgents/com.gepetel.agent.plist <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.gepetel.agent</string>
  <key>ProgramArguments</key>
  <array>
    <string>$(which node)</string>
    <string>$PWD/dist/index.js</string>
    <string>run</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>$HOME/Library/Logs/gepetel-agent.log</string>
  <key>StandardErrorPath</key><string>$HOME/Library/Logs/gepetel-agent.log</string>
</dict></plist>
EOF
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.gepetel.agent.plist

Its log is at ~/Library/Logs/gepetel-agent.log. To stop it: launchctl bootout gui/$(id -u)/com.gepetel.agent. A sleeping Mac simply shows as offline, and reconnects by itself when it wakes.

What it can and can't reach

  • Only your own private chat. A paired computer belongs to one chat, and every request is checked against it. No group can reach it, and neither can anyone else's chat.
  • It dials out. Nothing listens on the Mac, no port is forwarded, no tunnel is installed.
  • One credential, on your disk. Pairing stores a device token in ~/Library/Application Support/Gepetel/agent.json, readable only by you. Gepetel's side keeps only a hash of it.
  • Pages, not your files. Reading a page cannot touch your disk, and it refuses addresses inside your home network — so a web page can't talk Gepetel into opening your router.
  • Off whenever you like. gepetel-agent unpair on the Mac, or tell Gepetel in the chat to disconnect it — either way the token stops working.
Something not working? Tell Gepetel in the chat and ask it to pass a note to its creator — include what the Terminal said.
