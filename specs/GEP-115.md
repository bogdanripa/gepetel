# GEP-115: Log DM tool calls the way group tool calls are logged

## Goal
A daily review has to answer "did he actually do it, or only say so?" from the container log. Every
group tool call already leaves a line (`Tool call: <name> with args: …`, the group `dispatch` in
`src/oai.ts`). The 1:1 loop's `dispatch`, which wraps `dmDispatch`, logs nothing. So a DM reply like
"Am setat remindere…" leaves no trace of whether `set_reminder` ran, and the only way to check is
to read Mongo directly.

## Behaviour
1. **One line per DM tool call, before it runs.** It goes in the DM `dispatch` wrapper passed to
   `runToolLoop` (the one that calls `dmDispatch`), so every DM tool is covered and no branch inside
   `dmDispatch` can skip it. Shape it like the group line, labelled with the conversation:
   `Tool call (dm <userId>): <name> with args: <json>`
   (`<userId>` is the same id already used in the loop's `label: \`dm ${userId}\``.)
2. **One line per DM tool call, after it returns:** `Tool result (dm <userId>): <name> ok`, or
   `Tool result (dm <userId>): <name> error: <message>` when `dmDispatch` throws (log it, then
   rethrow, so error handling stays as it is) or when the result is an object with an `error`
   field. The result body is **not** logged: only the status. The message is cut to about 200
   characters.
3. **Secrets are redacted before logging.** Credential-bearing args are replaced with `"[redacted]"`:
   at least every value inside `headers` (`add_mcp_connector`: `Authorization`, `X-API-Key`, …),
   and any arg whose whole key name (case-insensitive, at any depth) is one of `token`,
   `access_token`, `refresh_token`, `secret`, `client_secret`, `password`, `api_key`, `apikey`,
   `authorization` or `key`. Whole names, not substrings, so `keywords` or `memory_key` are left alone. Redaction works on a copy: the args the tool receives are unchanged.
   Put the redaction in a small pure function (e.g. in `src/util.ts`) with a unit test.
4. Calls whose args are already summarised elsewhere (e.g. `memoryArgsBrief` for memory) may use
   that brief instead of the raw JSON. Not required.

## Acceptance criteria
- A DM that makes Gepetel set a reminder leaves, in the container log, a `Tool call (dm …): set_reminder with args: …`
  line and a matching `Tool result (dm …): set_reminder ok` line.
- A DM tool call that fails leaves a `Tool result … error: …` line, and the user-facing behaviour of
  the failure is unchanged.
- `add_mcp_connector` with `headers: {"Authorization": "Bearer abc"}` logs `"Authorization":"[redacted]"`
  and never `abc` (unit test on the redaction function).
- Group logging is unchanged.
- The tests that cover the change pass (`node scripts/test-changed.mjs`).

## Out of scope
- Logging full tool results or model output.
- Redacting message content in group or DM logs (the group line already logs args as they are; this
  issue only matches it, plus redacts credentials).
- Changing any tool's behaviour or the prompt (so no replay is needed).
